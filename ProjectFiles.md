# Directory: RideWise/

This document outlines the structure and purpose of each file within the RideWise project.

## `.dvcignore`

Specifies files and directories that should be ignored by DVC (Data Version Control). This is used to exclude temporary files or local configurations from DVC tracking.

## `.gitignore`

A standard Git ignore file, listing files and directories that should not be tracked by Git. This includes dependency folders (`node_modules`, `__pycache__`), environment files (`.env`), and OS-specific files.

## `appspec.yml`

The Application Specification file for AWS CodeDeploy. It defines the deployment actions to be taken on the EC2 instance, such as where to place the application files and which scripts to run during different deployment lifecycle hooks (`BeforeInstall`, `ApplicationStart`).

## `dvc.lock`

A lockfile generated by DVC to record the exact versions of dependencies and outputs for each stage in the pipeline. This ensures reproducibility.

## `dvc.yaml`

Defines the stages of the machine learning pipeline orchestrated by DVC. It outlines the commands to run for each stage (`data_ingestion`, `model_training`, etc.), their dependencies, parameters, and outputs.

## `Makefile`

Contains a set of `make` commands for common development tasks, such as installing dependencies (`requirements`), cleaning the project (`clean`), linting and formatting code (`lint`, `format`), and running tests (`test`).

## `params.yaml`

A configuration file that stores parameters for the DVC pipeline stages. This allows for easy modification of hyperparameters, data processing settings, and other constants without changing the source code.

## `pyproject.toml`

A modern Python project configuration file. It specifies the build system (`flit`), project metadata (name, version, author), and tool configurations (like `ruff` for linting).

## `README.md`

The main project documentation, providing a high-level overview of the RideWise application, its features, architecture, and setup instructions for local development.

## `requirements.txt`

Lists the Python dependencies required for the entire project, including the backend and the ML pipeline.

# Directory: `.dvc/`

Contains DVC's internal files, including configuration and cache tracking.

## `.dvc/config`

The main configuration file for DVC, specifying the remote storage location. In this project, it is configured to use an S3 bucket named `ridewisebucket`.

# Directory: `.github/workflows/`

Contains CI/CD workflow definitions for GitHub Actions.

## `.github/workflows/cd.yaml`

Defines the **Continuous Deployment** pipeline. It is triggered by a successful run of the CI workflow on the `main` branch. Its jobs include:

- Building Docker images for the frontend and backend.
- Pushing the images to Amazon ECR.
- Packaging and uploading deployment artifacts to S3.
- Triggering a new deployment in AWS CodeDeploy.

## `.github/workflows/ci.yaml`

Defines the **Continuous Integration** pipeline. It is triggered on pushes and pull requests to the `main` branch. Its jobs include:

- Setting up the Python environment and installing dependencies.
- Pulling data from DVC remote storage.
- Running automated tests using `pytest`.
- Promoting the newly trained model in the MLflow registry if tests pass.

# Directory: `backend/`

Contains the source code for the FastAPI backend application.

## `backend/.gitignore`

Specifies files to be ignored by Git within the backend directory, such as local data and model files.

## `backend/Dockerfile`

A multi-stage Dockerfile for building a production-ready, optimized Docker image for the FastAPI backend.

## `backend/config.py`

Uses Pydantic to manage all configuration settings for the backend, including paths, API settings, and environment variables loaded from a `.env` file.

## `backend/main.py`

The main entry point for the FastAPI application. It initializes the app, configures CORS middleware, and includes the API routers for predictions and regions.

## `backend/requirements.txt`

Lists the Python dependencies specifically required for the backend service, such as `fastapi`, `mlflow`, and `xgboost`.

## `backend/classes/predictor.py`

Contains the core prediction logic. The `TaxiDemandPredictor` class is responsible for:

- Loading the "champion" model from the MLflow Model Registry.
- Simulating the current time to match the historical dataset.
- Computing features and making predictions using the loaded model.

## `backend/routers/predictions.py`

Defines the FastAPI routes for serving predictions:

- `/api/predict/{region_id}`: Predicts demand for a specific region and its neighbors.
- `/api/predict-all`: Predicts demand for all regions.

## `backend/routers/regions.py`

Defines the `/api/regions` route, which returns a static JSON object containing the coordinates and names of all predefined taxi regions.

## `backend/utils/haversine.py`

A utility module containing the `haversine_distance` function to calculate the distance between two GPS coordinates.

# Directory: `deploy/scripts/`

Contains shell scripts used by AWS CodeDeploy during the deployment process.

## `deploy/scripts/install_dependencies.sh`

A script that runs on the EC2 instance to install necessary system dependencies like Docker and the AWS CLI before the application is started.

## `deploy/scripts/start_application.sh`

A script that runs on the EC2 instance to start the application. It handles:

- Logging into Amazon ECR.
- Stopping and removing old Docker containers.
- Pulling the latest Docker images.
- Fetching secrets from AWS SSM Parameter Store.
- Starting the new frontend and backend containers.

# Directory: `frontend/`

Contains the source code for the React frontend application.

## `frontend/Dockerfile`

A multi-stage Dockerfile that builds the React application and serves the static files using an Nginx web server.

## `frontend/nginx.conf`

The Nginx configuration file for the frontend Docker container. It handles serving the React app, managing SSL (HTTPS), and proxying API requests from `/api/` to the backend service to avoid CORS issues in production.

## `frontend/package.json`

Defines the frontend project's metadata, scripts (`start`, `build`, `test`), and lists all Node.js dependencies like `react`, `leaflet`, and `axios`.

## `frontend/public/index.html`

The main HTML template for the React single-page application. The React app is mounted onto the `<div id="root"></div>` element.

## `frontend/src/App.js`

The main component of the React application. It manages the overall state, orchestrates API calls, and renders all other sub-components.

## `frontend/src/index.js`

The entry point of the React application, where the main `App` component is rendered into the DOM.

## `frontend/src/App.css`, `frontend/src/index.css`

CSS files providing global styles and specific styles for the `App` component, defining the dark theme and layout.

## `frontend/src/components/DemandChart.js`

A React component that uses the `recharts` library to display taxi demand predictions as a bar chart.

## `frontend/src/components/Map.js`

A React component that uses `react-leaflet` to render an interactive map, displaying demand predictions as circle markers.

## `frontend/src/components/RegionSelector.js`

A React component that renders a dropdown menu, allowing users to select their region of interest.

## `frontend/srcs/components/StatsCard.js`

A reusable React component for displaying a single statistic, such as "Total City Demand," in a visually appealing card.

## `frontend/src/services/api.js`

An `axios`-based service module that centralizes all API calls to the backend, making it easy to manage endpoints and base URLs.

# Directory: `ridewise/`

Contains the Python scripts that form the stages of the DVC machine learning pipeline.

## `ridewise/data_ingestion.py`

The first stage of the ML pipeline. This script reads raw taxi data, filters it based on geographical coordinates and fare amounts, and saves the cleaned data for the next stage.

## `ridewise/data_preprocessing.py`

The second stage. This script takes the ingested data, uses `MiniBatchKMeans` to cluster pickup locations into 30 regions, and then resamples the data into 15-minute intervals, counting the pickups in each.

## `ridewise/feature_engineering.py`

The third stage. It creates a variety of time-series features from the preprocessed data, including time-based features (hour, day of week), lag features, rolling statistics, and historical averages.

## `ridewise/model_training.py`

The fourth stage. This script trains an `XGBoost` regressor on the engineered features, evaluates its performance, and logs the model, parameters, metrics, and artifacts to MLflow. It also registers the model in the MLflow Model Registry under a "development" name.

## `ridewise/promote_model.py`

A script used in the CI pipeline. After tests pass, it copies the latest "development" model to a "production" model in the MLflow Registry and assigns it the "champion" alias, marking it as the best model for production use.

# Directory: `tests/`

Contains automated tests for the project.

## `tests/test_data.py`

A `pytest` test suite that validates the ML model and data. The tests include:

- Checking that the model can be loaded from MLflow.
- Asserting that the model's performance on a test set is above a certain threshold.
- Verifying the integrity of the data, ensuring it has the correct columns and no missing values.
- Checking that data values are within their expected ranges.
